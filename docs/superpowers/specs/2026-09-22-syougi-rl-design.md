# SyougiRL 設計書

## 目的

Windows 上で動く将棋強化学習プロジェクトを構築する。短時間で動作確認できる
自己対戦学習を出発点に、設定変更だけで学習量を増やせるようにする。学習済みの
Checkpoint を選択し、人間と高速に対局できるデスクトップ GUI も提供する。

## 利用者と成功条件

利用者は Python/Jupyter 環境で学習を実行し、生成された Checkpoint を GUI で
選んで対局する。初期プリセットで少数の自己対戦と更新を完了して
`checkpoints/epoch_000001.pt` を生成できること、GUI でそのファイルを選択して
対局できることを最小成功条件とする。

駒または持ち駒を選択した際、合法な移動先・打ち先が盤面上で視認できる。

## 技術選定

* Python 3.11 以上
* PyTorch: 方策・価値ネットワークの訓練と推論
* python-shogi: 正確な局面・合法手・終局判定・SFEN/USI 処理
* PySide6: Windows デスクトップ対戦 GUI
* PyYAML: 学習・推論設定
* pytest: 単体テスト

強化学習は AlphaZero 型の小規模自己対戦を採用する。Stable-Baselines3 は将棋の
可変で巨大な合法手空間と自己対戦に対する適合性が低いため採用しない。

## モジュール構成

```text
syougi_rl/
  game/       # python-shogi ラッパー、特徴量、合法手と行動IDの変換
  model/      # PyTorch 方策・価値ネットワークと Checkpoint I/O
  training/   # MCTS自己対戦、リプレイバッファ、GPU学習ループ
  engine/     # Checkpoint 推論、時間/探索数制限つきMCTS
  gui/        # PySide6盤面、設定、AIワーカースレッド
train.py      # YAML駆動のバッチ学習CLI
notebooks/train.ipynb  # 共通学習APIを呼ぶ対話的な学習例
config/default.yaml
checkpoints/
tests/
README.md
```

Notebook と CLI は同一の `training` API を呼び、Notebook 専用の学習実装を持たない。
GUI は対戦専用であり、学習の開始・設定編集は行わない。

## 学習設計

局面を複数チャネルのテンソル（駒種・色・持ち駒・手番）にエンコードする。
Residual CNN は行動空間全体の方策 logits と、局面価値を返す。合法手だけを
マスクした方策を MCTS の事前確率に用いる。

自己対戦では MCTS の訪問回数を温度付き方策に変換して手を選択する。各局面の
特徴量・探索方策・最終勝敗をリプレイバッファへ格納し、ミニバッチで方策損失と
価値損失を最小化する。ゲーム終了には最大手数を設け、引き分けとして扱う。

`config/default.yaml` に短時間プリセットを既定値として置き、自己対戦局数、
1手当たりの探索数、更新回数、バッチサイズ、最大手数、保存間隔を調整可能にする。
`train.py` は設定ファイルと任意の上書き引数を受け付ける。

## GPU/CPU 方針

`device: auto` を既定とする。PyTorch の CUDA 可用性を調べ、使える場合は RTX 4070
を含む NVIDIA GPU で学習と推論を行い、使えない場合は CPU へ自動フォールバック
する。指定 CUDA で実行に失敗した場合も、説明可能なメッセージを出して CPU での
再実行を提案する。Checkpoint のロードは `map_location` を使い、GPU で作成した
ファイルを CPU 環境でも読み込めるようにする。

## Checkpoint

保存先は `checkpoints/`、ファイル名はゼロ埋めの世代番号を使う。

```text
epoch_000001.pt
epoch_000050.pt
```

各 Checkpoint にはモデル重み、最適化器状態、epoch、学習設定、行動空間のバージョンを
保存する。推論はモデル重みと互換性検査に必要なメタデータだけを利用する。

## 対戦 GUI

GUI の開始画面では、`checkpoints/` を一覧表示し、任意の `.pt` ファイルを
ファイルダイアログから選択できる。先手/後手と探索強度（MCTS回数または短時間の
即時方策）を指定して対局を開始する。

盤面では自分の駒を選択すると全ての合法な移動先に半透明マーカーを描画する。
持ち駒を選択した場合は合法な打ち先を表示する。選択解除、手の確定、任意の成りの
選択、手番・終局表示を提供する。合法手・終局は常に python-shogi の結果に従う。

AI 探索はワーカースレッドで実行し、GUI のイベントループを停止させない。AI は
`auto` デバイスによりGPU優先、利用不能時CPUの順に使う。

## エラー処理

* Checkpoint が欠落・破損・モデルと非互換なら、理由を示して対局を開始しない。
* CUDA が利用不能なら、CPUへ切替したことを画面とログに示す。
* 推論ワーカーの例外はメインスレッドへ通知し、盤面を不整合な状態にしない。
* 設定値が不正なら、CLI/Notebook の実行前に項目名と許容値を示して停止する。

## 検証

pytest で以下を検証する。

* 初期局面、持ち駒、成りの局面で合法手と行動IDを正しく往復できる。
* 特徴量の形状と手番による表現が正しい。
* 方策マスクが違法手を選ばず、モデル出力形状が仕様に一致する。
* Checkpoint の保存・ロード、GPU作成CheckpointのCPUロード、デバイス自動選択。
* 小規模学習設定が Checkpoint を生成し、推論エンジンが合法手を返す。

手動確認では、Notebook と `train.py` の両方で短時間プリセットを動かし、生成された
Checkpoint をGUIで選択して対局する。選択した盤上駒・持ち駒の合法手マーカー、成り、
CPUフォールバックも確認する。
